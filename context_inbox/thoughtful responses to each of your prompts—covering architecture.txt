4. Calibration: Decorator Quality Score (DQS) vs. False Positive Rate of a Decision Guard (Frontier graph + strictness)
You want a quantitative calibration guidance: how strict must +++Constraint(strictness=X) be so that a downstream deterministic Decision Guard has a 0% rejection rate at the Guard? This is fundamentally a question about precision–recall tradeoffs, guard calibration, and decorator-induced input quality. In other words, decorator quality controls the distribution of Planner/LLM outputs—especially confidence signals—and the Decision Guard’s behavior is driven by thresholds (confidence, risk, rules, etc.). A “0% rejection rate” is the naive ideal where the Guard never blocks; but that can come with an unacceptably high false acceptance rate (allowing bad outputs) unless the decorator quality is very high or the Guard is driven by very permissive rules.

How to frame and model this
We will model DQS (Decorator Quality Score) as a metric that characterizes how well the decorators correctly control output behavior: the likelihood that the decorated LLM/prompt produces outputs that are consistent with constraints, plus the calibration of the confidence signal it returns. For instance, DQS could be a weighted score combining:

Constraint adherence accuracy (fraction of outputs that satisfy schema + routing rules + safety / policy),
Confidence calibration error (expected miscalibration: how far the predicted confidence deviates from true risk),
Instruction clarity / conflict reduction (how many decorator directives contradict or cancel each other),
Output predictability (how stable outputs are under small input changes or decorator perturbation).
The Decision Guard is a deterministic classifier with a single operation: given (payload, confidence, context), it allows or denies. Let’s define:

False Positive Rate (FPR) at the Guard = P(Guard blocks a legitimate, actually-safe request) — this is the rate of unnecessary rejections.
Let the true “acceptability quality” be a function A of the payload (operationally, A=1 if the action is safe/valid given the full system state). The Planner outputs confidence C (a score in [0,1]) that the payload is acceptable.
The Guard uses a threshold T: allow if C >= T, otherwise deny. So FPR at the Guard is P(C >= T and A=0)—it rejects legitimate items when confidence is misleadingly high or legitimate items are near the boundary.
We want FPR = 0%: P(C >= T and A=0) = 0 for all outputs under consideration, i.e., no legitimate payload is ever rejected. That implies either the confidence signal is perfectly calibrated for acceptability at the threshold (no false alarms when A=1 is near T) or the Guard’s threshold T is set so low that no legitimate item is blocked—but if T is too low, you also start allowing risky items (higher False Negative Rate and higher real risk). Conversely, if you want 0% rejection of legitimate items, you’re essentially asking for no false positives at guarding (the Guard doesn’t deny good requests), so you need the confidence distribution for acceptable outputs to be very high and well-separated from risky outputs, so that setting a permissive T does not hurt safety.
Now relate DQS to the quality of the confidence signal and constraint adherence. A higher DQS generally means:

The Planner produces better-calibrated confidence (closer match between confidence and actual acceptability).
The output-space is constrained by decorators: fewer malformed payloads, fewer rule-violating intents, better grounding, and thus smaller conditional variance in the decision signal.
The guard decision then maps more cleanly: high confidence corresponds to high acceptability, low confidence corresponds to low acceptability, so the Guard can choose T with less tradeoff pain (smaller FPR for the same true-negative performance).
So there is a frontier: you can plot DQS on the x-axis and FPR at the Guard on the y-axis. For a fixed guard threshold policy (or alternatively, for a target safety level), better DQS allows the Guard to achieve lower FPR while maintaining low risk. Conversely, poor DQS forces either high FPR (Guard rejects a lot of good requests because confidence is noisy) or high risk (Guard allows risky requests because confidence miscalibration makes the threshold too permissive).
